## Зачем меняли схему

Раньше на перевод/пополнение сервер ждал Python + IsolationForest (`spawnSync` до десятков секунд). Это ставило **в очередь все запросы** (логин, баланс, админка) — сайт «зависал».

Модель ещё давала сырой `final_score` часто > 1, и обычное пополнение «Альфа-Банк» считалось **новым получателем**. Отсюда 101/100 и ложные «мошенник».

Клиенту баллы показывать нельзя: это служебные данные.

---

## Что происходит в момент операции

1. `server/ml/features.mjs` → `buildFraudSample` собирает те же 8 фичей, что и при обучении.
2. Сразу считается **правилами** `assessRisk` (без Python):
   - старт **8 баллов**;
   - плюсы за нового **человека**-получателя, ночь, новое устройство, сумму к среднему чеку, нереалистичный размер;
   - пополнение банка / QR / служебное **не** `is_new_payee`;
   - потолок для обычного пополнения &lt; 30 000 ₽.
3. Итог 1–100 и подпись:
   - **Норма** — типичная операция;
   - **Терпимо** — слабые признаки, деньги идут;
   - **Мошенник** — крупно / новый получатель от ~30 000 ₽ / сумма ≥ 100 000 ₽ / нереализм.
4. На транзакцию пишется: `riskScore`, `riskLabel`, `riskExplain[]`, `mlFeatures`.
5. **Мошенник** → операция `held` (получатель ещё не получил) + счёт заморожен. Админ: Провести / Вернуть / Разморозить счёт.
6. Клиенту уходит обычный снимок **без** баллов. Заморозка звучит как «счёт временно ограничен», статус — «в обработке».

Python на этом пути **нет**. Поэтому список и прогноз в админке могут обновляться каждые 2 секунды.

## Как модель коллеги подключается

| Файл | Роль |
|------|------|
| `anti_fraud.joblib` | IsolationForest, как сохранил |
| `anti_fraud_infer.py` | `score_transfer(sample, is_night=0)` |
| `score.py` | stdin JSON → stdout JSON, поле `engine: anti_fraud.joblib` |
| `features.mjs` | фичи + `assessRisk` |
| `index.mjs` | отчёт админки, прогноз, список scored |
| `server/index.mjs` | вызов при платеже, заморозка, скрытие от клиента |

Локальный прогон модели (не прод-путь):

```bat
cd /d D:\AlfaKoshelekCR\server\ml
pip install joblib numpy scikit-learn==1.6.1
echo {"amount":50000,"amount_to_avg_ratio":4.2,"hour":2,"is_night":1,"is_new_payee":1,"login_attempts":5,"time_since_last_transaction":30,"is_new_device":1} | python score.py
```

Ответ вида `{"score":..., "final_score":..., "anomaly":0|1}`.  
`final_score` у тебя может быть &gt; 1 — в правилах мы это **не** умножаем на 100 как есть (иначе 101/100). Если снова включим Python в горячий путь, нормализуем: `> 1.5` считаем шкалой 0–100.

## Фичи (имена как в joblib)

| Имя | Смысл |
|-----|--------|
| `amount` | \|сумма\| |
| `amount_to_avg_ratio` | к среднему **списанию** пользователя |
| `hour` | 0–23 |
| `is_night` | 23:00–06:00, у тебя вес после IsolationForest |
| `is_new_payee` | первый перевод **человеку**, не банку |
| `login_attempts` | от 1 |
| `time_since_last_transaction` | секунды |
| `new_device` / `is_new_device` | новая пара аккаунт + `X-Device-Id` |

IsolationForest ждёт:  
`amount`, `amount_to_avg_ratio`, `hour`, `login_attempts`, `is_new_payee`, `time_since_last_transaction`, `is_new_device`.

## Админка

- **Операции** — у каждой строки баллы + расшифровка («базовые 8 · новый получатель +5»).
- **ML / прогноз**
  - «Все операции» — новые сверху, сразу после платежа;
  - «Аномалии» — только Терпимо и Мошенник;
  - график: 7 дней **факта** (списания+пополнения) и 7 дней прогноза.
- Кнопки: Заморозить / Провести / Вернуть / Разморозить счёт.

`GET /api/admin/ml` — отчёт.  
`GET /api/admin/ml/features` — ряды для обучения.

## Как обновить свою модель

1. Положи новый `anti_fraud.joblib` рядом с `anti_fraud_infer.py`.
2. Бандл: `model`, `features`, `threshold`, `night_weight`, `min`, `max`.
3. Сигнатура `score_transfer` та же — обёртку не трогаем.
4. Другой набор фичей — напиши в `features.mjs` или скажи поля.

Чтобы снова гонять joblib на платеже — только через **асинхронный** вызов, не `spawnSync` внутри общего лока сервера.
