## Два поля модели — и всё

Модель отдаёт **два поля**. Бэкенд сам фрод не решает: нет z-score, нет баллов по клиенту, нет шкалы «из 100».

| Поле | Что это | Что видно в админке |
|------|---------|---------------------|
| `anomaly` | `0` или `1` | метка **Норма** или **Фрод** |
| `final_score` | непрерывный скор, **не вероятность** | число `round(final_score × 100) / 100`, например `0.66` или `1.12` |

Порог сидит внутри joblib. Его читает только `anti_fraud_infer.py`. Если модель не ответила, в админке **нет оценки**, а не «Норма».

Клиенту **ни метка, ни число не отдаются**. В ответе `/api/me` и снимке кошелька поля `ml*` / `risk*` вырезаются. При отказе клиент видит нейтральное «Операция отклонена…», без score.

## Что происходит в момент операции

1. `features.mjs` → `buildFraudSample` собирает фичи под `bundle['features']`.
2. `score.py` вызывает твой `score_transfer` и возвращает `{ score, final_score, anomaly }`.
3. Решение: **только** `anomaly === 1` → перевод / QR / массовый / пополнение отклоняются.
4. На транзакцию пишется `mlScore` (= `final_score`) и `mlAnomaly`. Если Python не ответил, оба поля пустые, платёж не помечается фродом.
5. Админка пишет метку из `anomaly` и число `final_score`.
6. Ручная заморозка в админке — отдельно, это не решение модели.

Z-score, «Мошенник / Терпимо» и риск клиента баллами из админки убраны.

Отдельного размеченного CSV на GitHub нет. В модель уходят фичи новой операции, которые сервер собирает в момент платежа. Список колонок — `bundle['features']` в `anti_fraud.joblib`.

### Что из этого видно в админке

- `anomaly = 0`: платёж сохраняется. Вкладки **Операции**, карточка клиента и **ML / прогноз** показывают **Норма**, число `round(final_score × 100) / 100` и шкалу `min(100, round(final_score × 100))`. Пересчёт модели идёт в фоне и не останавливает сервер.
- Список «Фрод» — только строки с `anomaly = 1`.
- `anomaly = 1`: платёж отклоняется до записи. В списке операций его нет. Клиент видит «Операция отклонена…» без скора; `final_score` остаётся в логе сервера.
- QR кассы скорится как получатель `QR-касса`. Если в коде кошелёк другого клиента, это перевод ему, и в модель уходит его телефон. Сам код — ссылка `/pay?to=&sum=&name=`; на скоринг формат ссылки не влияет.
- Клиенты и операции лежат в PostgreSQL (`DATABASE_URL`) на боевом сервере. Для скоринга платежа сервер читает операции только этого `email`, и сам вызов модели идёт до короткой транзакции списания. Пароль и PIN — хеш scrypt. Код на телефон уходит в Telegram, в базе это SHA-256, в админку не выводится. Полное описание проекта для Дани: `docs/dlya-dani-ivanenko.md`. Пополнение ограничено 100 000 ₽ за раз и 300 000 ₽ в день. Лимиты клиента нельзя поднять выше значений по умолчанию. Кабинет администратора в браузере держит HttpOnly-cookie 12 часов, выход её гасит. У клиента в профиле есть светлая тема; на скоринг, `anomaly` и `final_score` она не влияет. Устанавливаемые приложения Windows, Mac, Android и iOS — тот же клиент: они вызывают тот же `/api`, модель и порог не менялись. Файлы антифрода не менялись. Жест «назад» в приложении возвращает на предыдущий экран и к скорингу не относится. Массовый платёж теперь всегда требует код с почты (кроме демо); каждая строка скорится как раньше, порог 0.71 тот же. Вход по отпечатку или лицу — проверка устройства, в модель и в админский скор не входит.

Карточка «Прогноз» на главной считает ожидаемые расходы до конца текущего месяца: расходы клиента с 1-го числа делятся на сегодняшний день месяца и умножаются на оставшиеся дни. Это не скоринг и не график оборота в админке. `anomaly` и `final_score` не меняются.

Рекомендации — отдельный контур, на скоринг не влияет. `GET /api/recommendation` для вошедшего клиента считает таблицы так же, как итоговый ноутбук: `diff_days` и `amount_change_90` по `mcc_code`, доли по регулярным выражениям на `mcc_description`, кластер — ближайший сохранённый пример из `recommended_clusters.joblib`. В Gemini уходит тот же текст запроса и те же три поля: `регулярность`, `кластер`, `описание_групп`, с `code_execution`. Сначала вызывается `gemini-3.5-flash-lite`. Если она отвечает 503, тот же запрос уходит в `gemini-3.1-flash-lite`. Ключ берётся из `GEMINI_API_KEY`. Под текстом рекомендации на главной кнопка «Обсудить рекомендацию» открывает отдельный чат: `POST /api/recommendation/chat` дописывает реплики к тому же первому запросу и ответу Gemini. Это не чат поддержки. В админке этой ручки нет. `anomaly` и `final_score` считаются по-прежнему. В образ сервера добавлен pandas 2.2.3, его требует `recommend.py`. Файлы антифрода не менялись.

## Файлы

| Файл | Роль |
|------|------|
| `anti_fraud.joblib` | IsolationForest, как сохранил |
| `anti_fraud_infer.py` | `score_transfer(sample)` → `anomaly` + `final_score` |
| `score.py` | stdin JSON → stdout JSON, поле `engine` |
| `features.mjs` | сбор фичей |
| `index.mjs` | отчёт админки, прогноз, scored |
| `server/index.mjs` | вызов на платеже, отказ по `anomaly`, скрытие от клиента |
| `recommend.py` | функции регулярности и кластера для одного клиента |
| `recommended_clusters.joblib` | scaler, примеры HDBSCAN и описания групп; имя файла из ноутбука |
| `recommend_infer.py` | stdin JSON списаний → stdout JSON рекомендации |
| `recommend.mjs` | вызов infer из `GET /api/recommendation` |

## Как обновить модель

1. Положи новый `anti_fraud.joblib` рядом с `anti_fraud_infer.py`.
2. Бандл: `model`, `features`, `threshold` (сейчас 0.71), `min`, `max`.
3. Сигнатура `score_transfer` та же — обёртку не трогаем.
4. Другой набор фичей — напиши в `features.mjs` или скажи поля.

## Чего не делать
