# API «Альфа Кошелёк ЦР»

Базовый адрес боевого сервера: `https://alfa-koshelek-cr.fly.dev`. Локально сервер слушает порт из `PORT` (по умолчанию `8787`).

Клиенты, операции, сессии и коды лежат в PostgreSQL. Строка подключения — `DATABASE_URL`. Без неё локальный сервер берёт `postgresql://alfa:alfa@127.0.0.1:5432/alfa` из `docker-compose.yml`. Пароль хранится как scrypt с солью.

Все методы ниже — JSON. Тело запроса: `Content-Type: application/json`. Ошибка всегда выглядит так:

```json
{ "error": "Текст для пользователя" }
```

Коды ответа: `200` успех, `400` данные или отказ операции, `401` нет доступа, `403` счёт заморожен там, где это проверяется отдельно, `404` нет объекта или метода, `500` сбой сервера.

Косой слэш в конце пути снимается: `/api/me/` и `/api/me` — один метод.

## Заголовки

| Заголовок | Кто шлёт | Зачем |
|---|---|---|
| `Authorization: Bearer <token>` | клиент после входа | сессия на 14 дней |
| `X-Device-Id` | клиент | устройство. Если заголовка нет, сервер считает отпечаток из браузера и IP |
| `X-Admin-Key` | админка | ключ из переменной `ADMIN_KEY`. Пользовательский токен админке не подходит |

Токен выдают вход, регистрация и сброс пароля. Выход удаляет токен. Чужой запрос на `/api/...` без токена получает `401` и текст «Нужна авторизация». Исключения: проверка живости, регистрация, вход, код, сброс пароля и вся админка.

## Снимок кошелька

Вход, регистрация, сброс пароля и почти каждое действие клиента возвращают одно и то же состояние. У входа в нём дополнительно есть `token`.

```json
{
  "token": "только у входа, регистрации и сброса пароля",
  "user": {},
  "wallet": {},
  "txs": [],
  "notes": [],
  "contacts": []
}
```

`user`: `email`, `lastName`, `firstName`, `middleName`, `phone`, `passport`, `walletId`, `createdAt`, `otpChannel` (`sms` или `email`), `frozen`, `loginAttempts`, `lastLoginAttempts`. Пароль и список устройств клиенту не отдаются. Причина заморозки клиенту тоже не отдаётся, только признак `frozen`.

`wallet`: `email`, `balance`, `savings` (массив `{ id, name, amount }`), `biometric`, `pin`, `hideBalance`, `limits`, `usage`.

`limits`: `day` 50000, `month` 100000, `op` 30000, `abroad` 10000, пороги `alertDay` 80, `alertMonth` 70, `alertOp` 90, `alertAbroad` 100. Числа можно сменить методом лимитов.

`usage`: сколько уже потрачено. `day` — переводы с начала суток, `month` — все расходы с начала месяца, `abroad` сейчас всегда 0.

`txs` — операции этого пользователя, новые сверху. Поля: `id`, `email`, `name`, `amount` (минус — списание), `type` (`expense` или `income`), `icon`, `category`, `createdAt` (миллисекунды), `comment`, `status`, `counterparty`, `balanceAfter`, `linkedTxId`. Статус `held` клиенту приходит как `pending`. Метки модели в этот список не попадают.

`notes`: `id`, `email`, `title`, `body`, `kind`, `createdAt`, `read`, необязательный `txId`. Служебные заметки про мошенничество клиенту не отдаются.

`contacts`: `id`, `email`, `name`, `phone`, `wallet`, `initials`, `color`, `favorite`. Поле `wallet` здесь — подпись контакта, не номер кошелька пользователя.

Время в ответах — unix-миллисекунды.

## Код подтверждения

Шестизначный код живёт 10 минут и сгорает после верного ввода. Повтор того же назначения раньше чем через 40 секунд отвечает `400` с текстом «Подождите N с перед повторной отправкой».

Ответ об отправке:

```json
{ "ok": true, "via": "sms", "masked": "+7 (900) ***-**-67", "ttl": 600, "fallback": false }
```

`via`: `telegram`, `sms`, `email`, `demo` (демо-аккаунт без кода). На телефон код уходит в Telegram: если номер ещё не привязан к боту, ответ `200` с `needLink: true` и `botUrl`, код пока не создаётся. `fallback: true` значит, что на телефон не ушло и код ушёл на почту. `masked` — куда отправили, с закрытыми цифрами. На боевом сервере код обязателен: если письмо и телефонный канал не ушли, вход и регистрация не продолжаются. С одного адреса не больше 30 таких запросов за 10 минут. Восемь неверных паролей подряд закрывают вход на 15 минут. Пять неверных кодов сжигают текущий код.

Если SMS и почта недоступны на входе или регистрации, ответ всё равно `200` с `via: "skip"`, и следующий шаг можно сделать без кода. Для платежа и сброса пароля так нельзя: будет `400`, код в хранилище снимается.

Платёжный код нужен, когда сумма строго больше 10 000 ₽ и это не демо-аккаунт `ivan@alfa.demo`.

## Клиент

### `GET /api/health`

Без токена. Жив ли сервер.

```json
{ "ok": true, "payOtpFrom": 10000 }
```

`otp` — те же поля, что у `GET /api/admin/notify`, без пароля почты. `payOtpFrom` — порог платежного кода.

### `POST /api/auth/request-code`

То же самое: `POST /api/otp/send`.

Общие поля: `purpose` (`login`, `register`, `pay`; иное считается входом), `channel` (`sms` или `email`).

Вход. Тело: `login` или `email`, `password`, `channel`. Пароль проверяется сразу. Неверный пароль увеличивает счётчик попыток и отвечает `400` «Неверный пароль». Демо-аккаунт отвечает `{ "ok": true, "via": "demo", "masked": "демо" }` и код не шлёт.

Регистрация. Тело: `email`, `phone`, `channel`. Почта и российский мобильный должны быть свободны.

Платёж. Нужен токен. Тело: `amount`, `channel`. Замороженный счёт — `403`. Сумма до порога — `{ "ok": true, "via": "skip", "masked": "" }`, SMS не отправляется.

### `POST /api/auth/register`

Тело: `email`, `password` (от 8 символов), `phone`, `code`, `channel`, `lastName`, `firstName`, `middleName`, `passport`.

Почта на домене `.demo` не принимается. После кода создаётся пользователь с номером `WLT-XXXXXXXX-ЦР`, кошелёк с балансом 0 и сессия. Ответ — снимок плюс `token`.

### `POST /api/auth/login`

Тело: `email` или `login`, `password`, `code`. Логин может быть телефоном. Демо-аккаунт входит без кода. Чужой или просроченный код и неверный пароль увеличивают счётчик попыток. Ответ — снимок плюс `token`.

### `POST /api/auth/forgot`

Тело: `login` (почта или телефон), `channel` (`sms`, иначе письмо). Замороженный счёт — `403` «Счёт заблокирован. Обратитесь в поддержку.» Демо отвечает `via: "demo"`. Иначе уходит код назначения `reset`.

### `POST /api/auth/reset`

Тело: `login`, `code`, `password` (от 8 символов). Меняет пароль и сразу открывает сессию. Ответ — снимок плюс `token`.

### `POST /api/auth/logout`

Удаляет токен из заголовка `Authorization`. Ответ: `{ "ok": true }`.

### `GET /api/me`

То же самое: `GET /api/state`. Снимок текущего пользователя. Нужен токен.

### `POST /api/transfer`

Тело: `payee`, `amount`, `comment`, `code`.

`payee` — почта, телефон, номер кошелька или точное имя. Если имя совпало с несколькими клиентами, перевод не создаётся: нужно указать телефон или кошелёк. Если найден один человек, ему создаётся входящая операция на ту же сумму, обе строки связаны через `linkedTxId`. Если не найден, деньги списываются только у отправителя.

Отказ `400`, операция не создаётся: пустая сумма, пустой получатель, перевод себе, замороженный счёт, лимит, нехватка баланса, нет кода свыше 10 000 ₽, отказ проверки операции. В последнем случае текст один: «Операция отклонена. Попробуйте позже или напишите в поддержку.» Успех — новый снимок.

### `POST /api/topup`

Тело: `{ "amount": 1000 }`. Зачисляет сумму как пополнение с карты. За один раз не больше 100 000 ₽, за календарный день не больше 300 000 ₽. Замороженный счёт, превышение этого потолка и отказ проверки — `400`, строка не создаётся. Код подтверждения для пополнения не требуется. Успех — снимок.

### `POST /api/qr`

Тело: `amount`, `payee`, `merchant`, `code`.

`payee` — номер кошелька, телефон или почта из ссылки QR. Свой кошелёк — `400` «Нельзя оплатить свой QR». Если `payee` указывает на другого пользователя, это перевод ему, категория «Переводы». Если такого пользователя нет, списание идёт как оплата кассы, имя берётся из `merchant` (по умолчанию «QR-касса»), категория «Прочее». Лимиты, баланс и код свыше 10 000 ₽ те же, что у перевода. Успех — снимок.

Сама картинка QR и адрес `/pay?to=&sum=&name=` — не методы API. Страницу открывает сайт, а деньги списывает только этот `POST`.

### `POST /api/bulk`

Тело: `rows` — массив `{ "name", "phone", "amount" }`, плюс `code`. Для любого живого счёта код обязателен на всю сумму и приходит только на почту (`POST /api/auth/request-code` с `purpose: "pay"` и `bulk: true`). Демо-счёт `ivan@alfa.demo` код не требует. Обычный перевод и QR по-прежнему просят код только свыше 10 000 ₽.

Сначала проверяются заморозка, лимит и код на общую сумму. Потом каждая строка отдельно: свой телефон, неверный номер, пустая сумма, нехватка баланса и отказ проверки увеличивают `fail` и не останавливают остальные. Успешная строка списывает деньги и, если телефон найден среди пользователей, зачисляет получателю.

Ответ — снимок и два счётчика: `{ "ok": 2, "fail": 1, "user": {}, "wallet": {}, "txs": [], "notes": [], "contacts": [] }`.

### `POST /api/contacts`

Тело: `name`, `phone`. Телефон — российский мобильный. Ответ — снимок, в нём новый контакт.

### `PATCH /api/contacts/:id`

Тело: `{ "favorite": true }`. Только свой контакт. Чужой id — `404` «Контакт не найден».

### `DELETE /api/contacts/:id`

Удаляет свой контакт. Ответ — снимок.

### `POST /api/notes/read-all`

Помечает прочитанными все уведомления пользователя.

### `POST /api/notes/:id/read`

Помечает прочитанным одно своё уведомление. Чужой id молча не меняется, ответ всё равно снимок.

### `PATCH /api/limits`

Тело, все поля необязательны: `day`, `month`, `op`, `abroad`, `alertDay`, `alertMonth`, `alertOp`, `alertAbroad`. Нечисло и число не больше нуля оставляют прежнее значение. Поднять лимит выше значений по умолчанию нельзя, снизить можно. Пороги предупреждений приводятся к диапазону от 1 до 100. Ответ — снимок.

### `PATCH /api/security`

Тело, все поля необязательны: `biometric`, `hideBalance`, `pin`, `otpChannel` (`sms` или `email`). Ответ — снимок.

### `POST /api/support`

Тело: `{ "text": "текст обращения" }`. Пустой текст — `400`. Создаёт прочитанное уведомление «Обращение в поддержку». Ответ — снимок.

## Админка

Каждый путь `/api/admin/...`, кроме входа и выхода, принимает `X-Admin-Key` или cookie `alfa_admin`. Cookie ставит `POST /api/admin/session` с телом `{ "key": "..." }`, она HttpOnly и живёт 12 часов. `POST /api/admin/logout` заканчивает эту сессию кабинета, в том числе если cookie уже скопировали. Неверный ключ — `401` «Неверный ключ администратора». Пользовательский токен здесь не проверяется. Пароль демо-счёта через обычный сброс не меняется.

Пользователь в админских ответах богаче клиентского: есть `devices`, `deviceCount`, `freezeReason`, `frozenBy`, `frozenTxId`, `frozenAt`. Пароль в ответ не входит: в базе лежит только хеш scrypt. Новый пароль задаётся полем `password` и сразу хешируется.

Операция в админке приходит целиком, включая статус `held` или `rejected` и поля метки: `mlAnomaly`, `mlScore`, `riskLabel` (`Фрод` или `Норма`), `riskScoreExact`, `riskScore`, `riskBar`.

### `GET /api/admin/notify`

Настройки отправки без секретов: `sms`, `email`, `smsFrom`, `smtpHost`, `smtpPort`, `smtpUser`, `smtpFrom`. Поле `smsruApiId` в ответе пустое, пароль SMTP не возвращается.

### `PATCH /api/admin/notify`

Тело может содержать `smsruApiId`, `smsFrom`, `smtpHost`, `smtpPort`, `smtpUser`, `smtpPass`, `smtpFrom`. Пустое поле оставляет прежнее значение. Ответ — тот же объект, что у GET, без пароля.

### `POST /api/admin/notify/test`

Тело: `channel` (`sms` или `email`), `phone`, `email`. Шлёт проверочный код `000000`. Ответ: `{ "ok": true, "via", "masked" }`.

### `GET /api/admin/overview`

Сводка: `users`, `frozen`, `totalBalance`, `txCount`, `volumeOut`, `volumeIn`, `txToday`, `newWeek`, `notify`, `audit` (последние 30 записей журнала).

### `GET /api/admin/txs`

Параметры строки: `q` — поиск по почте, имени, контрагенту и категории; `type` — `in`, `out`, `held`, `rejected`. Ответ: `{ "txs": [], "total": 0 }`. В `txs` не больше 300 последних подходящих строк.

### `POST /api/admin/txs/:id/hold`

Тело: `{ "reason": "необязательный текст" }`. Ставит операцию на паузу и замораживает счёт владельца. Ответ: `{ "ok": true, "tx": {} }`.

### `POST /api/admin/txs/:id/release`

Проводит операцию, которая была на паузе. Если это списание и получатель ещё не получил деньги, зачисление создаётся сейчас. Иной статус — `400` «Операция не заморожена».

### `POST /api/admin/txs/:id/reject`

Отклоняет операцию на паузе. Списание возвращается отдельной служебной операцией, зачисление снимается обратно.

### `GET /api/admin/users`

Список пользователей: поля админского профиля, `balance`, `txCount`, `codePending` (есть ли ещё живой код, без самого кода), `sessions`. Сессионный токен в базе хранится как SHA-256, открытый токен есть только у клиента. PIN в ответах не приходит, только `pinSet`.

### `GET /api/admin/users/:email`

Карточка: `user` (с `codePending` и `balance`), `wallet`, `txs`, `contacts`, `notes`. Почта в пути — в нижнем регистре, как она хранится. Ключ администратора задаётся только переменной `ADMIN_KEY` длиной от 16 символов. Старый опубликованный ключ на боевом сервере не принимается.

### `PATCH /api/admin/users/:email`

Тело: `email`, `phone`, `balance`, `password`. Меняются только переданные поля. Новая почта переносит кошелёк, операции, уведомления и контакты. Баланс здесь ставится числом напрямую, без отдельной операции. Ответ: `{ "ok": true, "email": "новый@адрес" }`.

### `DELETE /api/admin/users/:email`

Удаляет пользователя, кошелёк, его операции, уведомления, контакты и сессии. Ответ: `{ "ok": true }`.

### `POST /api/admin/users/:email/freeze`

Тело: `{ "reason": "необязательный текст" }`. Замораживает счёт.

### `POST /api/admin/users/:email/unfreeze`

Снимает заморозку.

### `POST /api/admin/users/:email/kick`

Удаляет все сессии пользователя. Текущие токены перестают работать.

### `POST /api/admin/users/:email/adjust`

Тело: `amount` (не ноль), `comment`. Плюс создаёт служебное зачисление, минус — служебное списание. Ответ вместе с пользователем и кошельком: `{ "ok": true, "user": {}, "wallet": {} }`. Тот же вид ответа у freeze, unfreeze, kick и password.

### `POST /api/admin/users/:email/password`

Тело: `{ "password": "от 8 символов" }`.

### `GET /api/admin/export`

Параметр `kind`: `users` (по умолчанию), `txs`, `audit`. Ответ: `{ "rows": [] }`. Для пользователей в строке есть баланс. Это полная выгрузка, не страница одного клиента.

### `GET /api/admin/ml`

Параметр `horizon` — горизонт прогноза в днях, по умолчанию 7. Ответ собирает модуль модели: `model`, `horizonDays`, `features`, `baseline`, `custom`, `forecast`, `history`, `scored`, `anomalies`, `generatedAt`, `today`. В `scored` и `anomalies` у операции есть `label` (`Фрод` или `Норма`), `scoreExact` и `scoreBar`. Как считается метка, описывает страница модели, не этот метод.

### `GET /api/admin/ml/features`

Срез для модели за 30 дней: `generatedAt`, `daily`, `users`, `txs`, `fraud`, `fraudFeatures`. Это входные ряды, не решение по платежу.

## Что не является методом

`GET /`, `GET /pay` и `GET /admin` отдают собранный сайт, не JSON. Платёж по QR всё равно делается через `POST /api/qr`. Неизвестный путь `/api/...` отвечает `{ "error": "Нет такого метода" }`.
