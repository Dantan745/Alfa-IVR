# Alfa Кошелёк ЦР — для Дани Иваненко

Даня, это описание того, как проект устроен сейчас и где в нём твоя модель. Живой сайт: https://alfa-koshelek-cr.fly.dev . Короткая заметка только про скоринг, которую мы держим рядом с моделью: `server/ml/METOD-RABOTY.md`.

Твои файлы не трогаем:

- `server/ml/anti_fraud.joblib`
- `server/ml/anti_fraud_infer.py`

Их вызывает обёртка `server/ml/score.py`.

## Что это за продукт

Веб-кошелёк цифрового рубля. Человек регистрируется, пополняет баланс, переводит деньги другому клиенту, платит по QR и массовым списком. Есть кабинет администратора: https://alfa-koshelek-cr.fly.dev/admin . Ключ кабинета — секрет сервера `ADMIN_KEY`, в репозитории его нет. В браузере ключ не хранится: после входа живёт HttpOnly-cookie 12 часов.

Клиентский интерфейс — React, сервер — Node.js, данные — PostgreSQL. Модель считается на сервере в момент платежа. Клиент ни метку, ни число не получает.

Демо-вход для проверки экранов: `ivan@alfa.demo` / `Demo1234`.

## Как платёж доходит до модели

1. Клиент отправляет перевод, QR, массовый платёж или пополнение.
2. Сервер проверяет сумму, заморозку, лимиты, баланс и при сумме больше 10 000 ₽ одноразовый код.
3. `server/ml/features.mjs`, функция `buildFraudSample`, собирает признаки новой операции. Список колонок — `bundle['features']` внутри joblib. Отдельного размеченного CSV в репозитории нет.
4. `score.py` вызывает твой `score_transfer` и возвращает JSON: `score`, `final_score`, `anomaly`, `engine`.
5. Решение принимается только по `anomaly`. Если модель ответила и `anomaly === 1`, платёж отклоняется до записи. Клиент видит «Операция отклонена. Попробуйте позже или напишите в поддержку.» Число в этот ответ не кладётся, оно остаётся в логе сервера.
6. Если `anomaly === 0`, операция записывается. В админке метка **Норма**, число `round(final_score × 100) / 100`, шкала `min(100, round(final_score × 100))`.
7. Вызов Python идёт до короткой транзакции списания. Если Python не ответил, полей оценки нет, и платёж из-за этого фродом не помечается.

`final_score` — непрерывный скор, не вероятность. Он может быть больше 1. Порог сидит внутри joblib (сейчас 0.71) и читается только `anti_fraud_infer.py`.

Z-score, баллы «мошенник / терпимо» и риск клиента числом из админки убраны. Ручная заморозка в кабинете — отдельное действие человека, это не ответ модели.

QR кассы скорится как получатель `QR-касса`. Если в коде кошелёк другого клиента, в модель уходит его телефон. Формат ссылки на скоринг не влияет.

## Что видно тебе в админке

Вкладка **ML / прогноз** считает отчёт по уже записанным операциям. Строка «Фрод» — только `anomaly = 1`. Отклонённый моделью платёж в список операций не попадает.

Поля `ml*` и `risk*` из ответа клиенту вырезаются в `publicTx`.

## Где лежит остальной проект

| Часть | Где |
| --- | --- |
| HTTP API, платежи, сессии | `server/index.mjs` |
| PostgreSQL, схема, запросы | `server/db.mjs` |
| Сбор признаков | `server/ml/features.mjs` |
| Отчёт админки | `server/ml/index.mjs` |

| Описание базы для Стёпы | `docs/dlya-styopy.md` |

Пароли и PIN — scrypt с солью. Токен сессии и код из Telegram в базе — SHA-256. Пополнение клиентом ограничено 100 000 ₽ за раз и 300 000 ₽ в день. Свои лимиты клиент может снизить и не может поднять выше значений по умолчанию.

## Как прогнать модель локально

```bat
cd /d D:\AlfaKoshelekCR\server\ml
pip install joblib numpy scikit-learn==1.6.1
echo {"log_amount":10.8,"amount_to_avg_ratio":4.2,"hour":2,"is_night":1,"is_new_payee":1,"login_attempts":5,"time_since_last_transaction":30,"is_new_device":1,"amount_to_balance":0.9} | python score.py
```

Ответ вида `{"score":..., "final_score":..., "anomaly":0|1, "engine":"anti_fraud.joblib"}`.

Чтобы подменить модель, положи новый `anti_fraud.joblib` рядом с `anti_fraud_infer.py`. В бандле нужны `model`, `features`, `threshold`, `min`, `max`. Имена признаков должны совпасть с тем, что собирает `buildFraudSample`.
